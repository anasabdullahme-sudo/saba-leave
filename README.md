# بوابة رفع الإجازات — سابا

| الرابط | لمين |
|---|---|
| `/` (index.html) | المريض: يختار النوع ← يصوّر التقرير ← الذكاء يعبّي البيانات ← يراجع ويرسل |
| `/staff` (staff.html) | الموظف: الفروع فوق + إشعارات حمراء، «في الانتظار» و«تم الرفع» |

**جرّبه الحين بدون إعداد:** افتح المجلد بأي سيرفر محلي (مثلاً `npx serve .`) — يشتغل «وضع تجريبي» على جهازك، وتقدر تفتح صفحة المريض والموظف في تبويبين وتشوف الطلب يوصل مباشرة.

---

## التشغيل الحقيقي (مرة وحدة ~20 دقيقة)

### 1) مشروع Firebase
1. ادخل [console.firebase.google.com](https://console.firebase.google.com) ← مشروع جديد (أو مشروعك الحالي).
2. فعّل خطة **Blaze** (الدفع حسب الاستخدام) — مطلوبة للتخزين وتعطي حدود أعلى للذكاء.
3. **Authentication ← Sign-in method**: فعّل **Anonymous** و **Email/Password**.
4. **Firestore Database ← Create** (اختر أقرب موقع متاح للسعودية).
5. **Storage ← Get started** (نفس الموقع).
6. **AI Logic ← Get started** ← اختر **Gemini Developer API**.
7. **App Check**: سجّل التطبيق بـ **reCAPTCHA Enterprise** وأضف دومين موقعك ← انسخ الـ Site key.
   (ابتداءً من 2 نوفمبر 2026 App Check إلزامي للذكاء الاصطناعي.)
8. **Project settings ← Your apps ← Web** ← انسخ `firebaseConfig`.

### 2) عبّ الإعدادات
افتح `shared.js` وعبّ أول جزء:
```js
export const firebaseConfig = { apiKey: "...", authDomain: "...", projectId: "...", storageBucket: "...", messagingSenderId: "...", appId: "..." };
export const RECAPTCHA_SITE_KEY = "...";
```

### 3) ارفع الموقع + القواعد
```bash
npm i -g firebase-tools
firebase login
firebase use --add            # اختر المشروع
firebase deploy               # يرفع الموقع + قواعد الأمان + الفهارس
```
- رابط المريض: `https://<project>.web.app`
- رابط الموظف: `https://<project>.web.app/staff`

> تقدر تستضيف على GitHub Pages بدال Firebase Hosting، بس ارفع القواعد بـ `firebase deploy --only firestore,storage` وأضف دومين GitHub في App Check.
> عند أول نشر لـ storage.rules بيطلب منك صلاحية ربط Storage بـ Firestore — وافق.

### 4) أضف الموظفين
1. **Authentication ← Users ← Add user** (إيميل + كلمة مرور لكل موظف).
2. انسخ **User UID**.
3. **Firestore ← Start collection** اسمها `staff` ← Document ID = الـ UID ← حقل `name` (string) = اسم الموظف.

أي حساب مو موجود في `staff` ما يقدر يدخل اللوحة ولا يشوف الصور.

## كيف يتوزع الطلب على الفرع
- الذكاء يقرأ **اسم الطبيب المطبوع** و**الطبيب اللي على الختم** كلٌّ لحاله (المريض يقدر يعدّل الاسم يدوي).
- **الختم له الأولوية**: إذا الختم لطبيب مدرج، الطلب يروح لفرعه حتى لو الاسم المطبوع مختلف، ويظهر للموظف وسم «بختم د. …».
- بعدها يطابق الاسم المطبوع مع قائمة الأطباء في `shared.js` (`DOCTORS`).
- أي طبيب غير مذكور ← **سابا البوادي**، ويظهر عليه وسم «طبيب غير مدرج».
- الموظف يقدر ينقل أي طلب لفرع ثاني من خانة «الفرع» داخل التفاصيل.
- **السليمانية**: ما فيه أطباء مسجلين لها حالياً — أضفهم في `DOCTORS` بنفس الشكل مع `branch: "sulaimaniyah"`.

إضافة طبيب:
```js
{ id: "new-doctor", branch: "tala", ar: "الاسم بالعربي", en: "English Name", alt: ["صيغة ثانية", "Other Spelling"] },
```

## الحالات في لوحة الموظف
- **في الانتظار** ← **تم الرفع**، أو ← **معلّق** بسبب: ترخيص الطبيب / خطأ في البيانات / أخرى (مع ملاحظة).
- الطلب المعلّق يرجع للانتظار بزر «إرجاع»، أو يتحول مباشرة لـ «تم الرفع».
- الإشعار الأحمر يحسب «في الانتظار» فقط.

## القراءة من تقرير سابا (أثير)
القراءة مضبوطة على قالب «Sick Leave Report» نفسه. تُعبّى تلقائياً الهوية الوطنية (مو رقم الملف) والاسم عربي وإنجليزي والميلاد والجوال وبداية الإجازة، والنهاية تنحسب من عدد الأيام، واسم الطبيب.
وللموظف تظهر بعد: رقم الملف والجنسية والجنس والسبب وختم الطبيب.

## السرعة والتحمّل
- الصورة تنضغط في جوال المريض (≈ 200–400KB) قبل الرفع.
- الرفع والقراءة الذكية يشتغلون **مع بعض** — المريض ما ينتظر واحد بعد الثاني.
- إذا الذكاء ما رد خلال 30 ثانية، المريض يكمل يدوي — ما يتعطل أبداً.
- Firestore / Storage / Gemini كلها تتوسع تلقائياً؛ ما فيه سيرفر تديره.
- لوحة الموظف تتحدث لحظياً (بدون تحديث الصفحة)، مع صوت تنبيه وإشعار متصفح.
- «تم الرفع» يحمّل آخر 30 ويكمّل بزر «عرض الأقدم» — ما يثقل حتى لو صار عندك مئات الآلاف.

## الموديل
`AI_MODEL = "gemini-3.5-flash"` (مستقر حتى مايو 2027 على الأقل). لو تبي دقة أعلى بخط اليد جرّب `gemini-3.8-flash` (أحدث لكن عمره قصير).

## إضافة «سابا ← صحة» (تعبئة صحتي تلقائياً)
المجلد `seha-extension/` إضافة كروم تثبّتها مرة وحدة على كل جهاز موظف:
1. افتح `chrome://extensions` وفعّل **Developer mode** (أعلى اليمين).
2. اضغط **Load unpacked** واختر مجلد `seha-extension`.
3. ثبّت الأيقونة (📌) عشان تبان.

**طريقة الشغل:** افتح الطلب في اللوحة ← اضغط «افتح صحة وعبّي تلقائياً» ← في صحة تطلع لوحة صغيرة يسار الشاشة:
- تحدد لك **الحساب الصحيح** في صفحة «حسابات صحة طبي» وتنبهك لو دخلت حساب فرع ثاني.
- تختار **نوع الإجازة** و**نوع الهوية** وتعبّي **الهوية والميلاد**، وبعد «تحقق» تعبّي خانات الخطوة الثانية تلقائياً.
- كل بيانات الطلب جنبها زر نسخ لأي خانة ما تعبّت.
- بعد الحفظ تلقط رقم **PSL** تلقائياً، وزر «تم الرفع — حدّث لوحة سابا» يحوّل الطلب لـ«تم الرفع» ويحفظ رقم صحة معه.
- **ما تضغط «تحقق» ولا «حفظ» أبداً** (كل طلب يخصم نقاط) — الموظف يراجع ويضغط بنفسه.

إذا رفعت اللوحة على دومين غير `anas-bit7.github.io` أو `*.web.app`، أضفه في `manifest.json` تحت `bridge.js`.
الخانات اللي تتعبى في الخطوة الثانية: رقم السجل الطبي، الجوال (9 أرقام بعد 966)، تاريخ الدخول (ميلادي + هجري أم القرى)، مدة الإجازة، من تاريخ (ميلادي + هجري)، والطبيب المعالج إذا تطابق الاسم. الخانات المعبّاة مسبقاً من صحة (الاسم، الهوية، الميلاد، الجنسية) ما تنلمس.
شكل التاريخ في `seha.js` → `DATE_FMT = "DD/MM/YYYY"`.

## حماية البيانات (ما تنحذف ولا تترست)
مصمم عشان ما يتكرر اللي صار في المواقع السابقة:
- **كل طلب مستند مستقل** — ما فيه ملف/قائمة وحدة تنكتب كاملة، فجهاز قديم مفتوح ما يقدر يكتب فوق إضافات غيره.
- **التعديل يلمس الخانة المعدّلة فقط** (`updateDoc`) — ما فيه حفظ للمستند كامل من نسخة قديمة.
- **الحذف ممنوع في القواعد** للكل (`allow delete: if false`) حتى لو صار خطأ في الكود.
- **ما فيه أي بيانات في المتصفح** (localStorage) ولا في ملفات GitHub — كل شي في Firestore.
- **قواعد دائمة** (مو Test mode اللي ينتهي بعد 30 يوم ويوقف القراءة فجأة).
- **ما فيه أي كود يعبّي أو يمسح البيانات عند التشغيل** — والوضع التجريبي يشتغل على جهازك فقط؛ على الموقع الحقيقي بدون إعدادات يوقف بدل ما يحفظ في المتصفح.

فعّل بعد من الكونسول (مرة وحدة):
1. **Firestore ← Disaster recovery ← Point-in-time recovery**: يرجّع البيانات لأي دقيقة خلال آخر 7 أيام.
2. **Firestore ← Disaster recovery ← Backups**: نسخة احتياطية يومية (احتفاظ 14 أسبوع مثلاً).
3. **Firestore ← Database settings ← Delete protection**: يمنع حذف قاعدة البيانات نفسها.

## نصيحة
احذف الصور القديمة تلقائياً (مثلاً بعد 90 يوم) من: Google Cloud Console ← Cloud Storage ← البكت ← Lifecycle ← Add rule ← Delete after 90 days.
